Odracir is a personal agentic system for quickly entering, understanding, and implementing work in a new research field. It is designed to help one person collect papers, translate and summarize them, extract structured knowledge, discuss the field with an agent, and gradually turn research understanding into executable plans and code.

The project currently targets the DeepSeek API through an OpenAI-compatible client interface.

## Product Goal

Odracir should become a research companion that can help you:

1. Build a local knowledge base from selected research papers.
2. Translate and summarize papers quickly.
3. Extract important concepts, methods, datasets, equations, experiments, limitations, and implementation clues.
4. Record paper-level information into a JSON index inside each research folder.
5. Chat with an agent that understands the accumulated papers.
6. Plan learning paths, experiments, reproduction steps, and code tasks.
7. Call code tools when implementation work is needed.

The first principle is practical acceleration: Odracir should help you enter a domain faster, not merely produce polished summaries.

## Initial Use Case

A typical research folder may look like this:

```text
research-folder/
  papers/
    paper-a.pdf
    paper-b.pdf
  notes/
  code/
  odracir_index.json
  research_catalog.json
```

You place selected papers in `papers/`. Odracir reads them, produces translations and summaries, extracts structured information, updates the operational `odracir_index.json`, and rebuilds the visible `research_catalog.json` so the folder gradually becomes a local research memory.

The current harness implements the local-first spine of this workflow: folder scanning, extraction, OCR routing, traceable chunks, retrieval, cited questions, versioned summary skills, summary audits, selective translation, and deterministic `research_catalog.json` rebuilding.

## Planned Capabilities

### Paper Intake

- Watch or scan a folder containing selected papers.
- Detect new PDFs or text documents.
- Extract title, authors, abstract, sections, references, and key figures when possible.
- Track whether each paper has already been processed.

### Translation and Summary

- Translate papers or selected sections into Chinese.
- Produce short, medium, and detailed summaries.
- Preserve technical terms and important equations.
- Highlight what is important for understanding and implementation.

### Structured Research Index

Each research folder should contain a JSON index, such as `odracir_index.json`, with structured records for all processed papers.

Possible fields:

```json
{
  "papers": [
    {
      "id": "paper-a",
      "title": "Paper Title",
      "authors": ["Author A", "Author B"],
      "year": 2026,
      "source_file": "papers/paper-a.pdf",
      "research_area": "field or topic",
      "core_problem": "what problem the paper solves",
      "main_contribution": "main idea or contribution",
      "methods": ["method 1", "method 2"],
      "datasets": ["dataset 1"],
      "experiments": ["important experiment"],
      "limitations": ["limitation 1"],
      "implementation_notes": ["code or reproduction clue"],
      "summary_short": "short summary",
      "summary_detailed": "detailed summary",
      "processed_at": "2026-05-30T00:00:00+08:00"
    }
  ]
}
```

### Research Conversation Agent

An agent should be able to:

- Answer questions using the papers already processed in the folder.
- Compare papers and explain relationships between ideas.
- Identify open questions and unresolved conflicts.
- Recommend what to read next.
- Help turn paper understanding into experiments or implementation tasks.

### Planning and Code Assistance

Odracir should later support:

- Reproduction planning.
- Environment setup planning.
- Code scaffolding.
- Experiment task decomposition.
- Debugging support.
- Calling local code tools when safe and useful.

## Proposed Agent Roles

The system can start with one agent and later split responsibilities when needed.

Initial single-agent role:

- `research_companion`: reads folder context, talks with the user, uses tools, and produces research or implementation guidance.

Possible future roles:

- `paper_intake_agent`: detects and processes new papers.
- `paper_summary_agent`: translates, summarizes, and extracts structured records.
- `research_memory_agent`: maintains and queries the folder-level JSON index.
- `planning_agent`: creates learning, reproduction, and implementation plans.
- `coding_agent`: helps scaffold code, run checks, and explain implementation details.
- `review_agent`: checks summaries, plans, and code for missing assumptions or weak evidence.

## Run

```powershell

```

Or:

```powershell
python -m odracir.cli "Help me summarize the current project goal."
```

Scan a research folder:

```powershell
odracir scan D:\Research\diffusion-models
```

This creates the folder if needed, ensures `papers/`, `notes/`, and `code/` exist, and writes or updates `odracir_index.json`.

Scan an existing custom paper folder:

```powershell
odracir scan "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage"
```

This keeps the research index in the `Mecidal World Model` folder while reading PDFs from the existing `Paper Storage` folder.

Extract PDF text:

```powershell
odracir extract "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage"
```

This writes extracted page-level text artifacts into `.odracir/texts/` and updates `odracir_index.json` with extraction status, page count, text length, and artifact paths.

Inspect optional document-tool availability:

```powershell
odracir capabilities
```

Use Docling for a complex-layout PDF after installing `pip install -e ".[docling]"`:

```powershell
odracir extract <research-folder> --paper <paper-id> --parser docling --force
```

Install the optional PyMuPDF4LLM backend and compare it with the lightweight default without changing research artifacts:

```powershell
pip install -e ".[pymupdf4llm]"
odracir benchmark-parsers <research-folder> --papers-dir <paper-folder> --limit 1
```

Cache conservative review recommendations after benchmarking:

```powershell
odracir recommend-parsers <research-folder> --papers-dir <paper-folder>
```

Recommendations are written under `.odracir/parser-routing/`. The default policy keeps `pymupdf` selected unless you explicitly review a paper and rerun `extract --parser pymupdf4llm --force`. A candidate enters the review queue only when it adds at least 1,000 characters and at least 3% more text.

Use the layout-aware Markdown backend selectively after reviewing the comparison:

```powershell
odracir extract <research-folder> --paper <paper-id> --parser pymupdf4llm --force
```

Create OCR-enhanced derivatives for PDFs reported as `needs_ocr` after installing `pip install -e ".[ocr]"` and OCRmyPDF's system dependencies:

```powershell
odracir ocr <research-folder> --papers-dir <paper-folder> --language eng
odracir extract <research-folder> --papers-dir <paper-folder>
```

OCR derivatives are written under `.odracir/ocr/`; source PDFs are not modified. The next extraction run automatically uses the current OCR derivative.

Inspect processing status, OCR needs, and failures:

```powershell
odracir status "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage"
```

Create stable, page-traceable chunks for successfully extracted PDFs:

```powershell
odracir chunk "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage"
```

Chunk artifacts are written into `.odracir/chunks/`. Re-running the command skips unchanged text artifacts.

Search local chunks with inspectable paper and page citations:

```powershell
odracir search "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" "world model" --limit 3
```

Preview the evidence selected for a folder-level research question without loading API configuration or calling DeepSeek:

```powershell
odracir ask "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" "How do medical world models predict clinical trajectories?" --query "medical world model clinical trajectories" --limit 4 --dry-run
```

Answer the question from the retrieved local evidence:

```powershell
odracir ask <research-folder> "<question>" --query "<focused retrieval query>"
```

The non-dry route explicitly calls DeepSeek and writes a reproducible answer artifact under `.odracir/answers/`. Answers, structured claims, and cached artifacts are checked against the retrieved citation allowlist.

Generate a cited summary for one chosen paper:

```powershell
odracir summarize "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage" --paper <paper-id>
```

This explicitly calls DeepSeek and consumes API usage. Odracir writes the result into `.odracir/summaries/`, records provider, model, prompt version, input hash, token usage, and citations, then skips unchanged summaries on later runs.

Inspect built-in research skills and preview biomedical summary scope without loading API configuration or calling DeepSeek:

```powershell
odracir skills
odracir skills biomedical-paper
odracir summarize "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage" --skill biomedical-paper --dry-run
odracir evaluate-summaries "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage" --skill biomedical-paper
odracir build-memory "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage"
```

`generic` remains the default cross-disciplinary skill. `biomedical-paper` adds versioned, evidence-aware fields for population, intervention or exposure, comparator, outcomes, mechanisms, assays or measurements, clinical relevance, and safety or ethics. Every structured biomedical item must preserve source citations or explicitly set `inference=true`. Executed summaries record the selected skill and version so changing skills invalidates stale summary caches.

`evaluate-summaries` is deterministic and does not call DeepSeek. It writes cached reports under `.odracir/evaluations/summaries/`, checks whether artifacts are missing or stale, revalidates citations against current chunks, and reports review warnings such as missing limitations or empty biomedical fields.

`build-memory` is also deterministic and does not call DeepSeek. It rebuilds the visible `research_catalog.json` from the compact index and audited summary artifacts. Missing, stale, or invalid summaries remain explicit; they are not silently treated as accumulated knowledge. The agent can read the same catalog ephemerally through `get_research_memory` without writing files.

Translate the default abstract, methods, and conclusion selection into Chinese:

```powershell
odracir translate "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage" --paper <paper-id>
```

```powershell
odracir translate "D:\大学课程资料\留学\暑研\NEU Wengong Jin\Mecidal World Model" --papers-dir "Paper Storage" --paper <paper-id> --dry-run
```

## Development Roadmap

1. Keep the first version as a single agent with a small tool registry.
2. Use the research-folder harness to create and update `odracir_index.json`.
3. Extract PDF text into local artifacts under `.odracir/texts/`.
4. Validate the typed `odracir_index.json` schema and inspect processing states.
5. Chunk extracted text into stable, page-traceable artifacts under `.odracir/chunks/`.
6. Review cached parser-routing recommendations and inspect representative PyMuPDF4LLM output before accepting per-paper overrides.
7. Review biomedical summary dry runs and run supervised DeepSeek summary and selective-translation benchmarks.
8. Benchmark and refine the cited `odracir ask` route before adding optional embeddings.
9. Validate the explicit OCRmyPDF route on a scanned fixture after installing system dependencies.
10. Add a research-companion agent that reuses the audited ask and retrieval paths.
11. Add planning tools for reading paths, reproduction, and experiments.
12. Add code assistance tools after research memory is stable.
13. Split into multiple agents only when the single-agent prompt becomes too large or conflicted.

## Design Principles

- Local-first: research folders should remain understandable without a remote database.
- Structured memory: important information should be written into JSON, not trapped only in chat history.
- Evidence-aware: answers should point back to papers or notes whenever possible.
- Incremental: build one reliable loop before adding multiple agents.
- Personal: optimize for one person's research speed, taste, and workflow.
